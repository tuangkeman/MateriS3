1. Pengantar Algoritma & Struktur Data

Dasar dari semua materi berikutnya: apa itu algoritma, apa itu struktur data, dan bagaimana keduanya membentuk sebuah program.

Definisi

  • Algoritma — langkah-langkah logis dalam menyelesaikan suatu masalah berbasis komputer. Pondasi dari teknologi informasi, termasuk kecerdasan buatan (LLM & GenAI). Bisa ditulis sebagai flowchart atau pseudocode.
  • Struktur Data — cara data diorganisir secara efektif & efisien di memori komputer agar bisa digunakan kembali, mencakup jenis data, sifat data, dan teknik CRUDS (Create, Read, Update, Delete, Select).
Program = Algoritma + Struktur Data. Struktur data menentukan cara menyimpan & mengakses data secepat apa; algoritma menentukan langkah apa yang dilakukan terhadap data itu.

Kriteria algoritma yang baik

KriteriaArti
FiniteLangkahnya pasti berakhir
DefiniteSetiap langkah jelas, tidak ambigu
InputMemiliki 0 atau lebih input
OutputMinimal menghasilkan 1 output
EffectiveSetiap langkah dapat benar-benar dikerjakan
Correct & EfficientHasilnya benar dan hemat sumber daya

Cara membuat algoritma (6 langkah)

1. Pahamimasalah yang dihadapi
2. Tentukaninput dan output
3. Pilihstruktur data yang cocok
4. Susunlangkah logis
5. Ujidengan contoh data
6. Analisisdan perbaiki (iteratif)

Kenapa butuh struktur data yang tepat?

Contoh klasik: cari nilai terbesar dari 5 data pakai 5 variabel (a,b,c,d,e) — kalau butuh cari terbesar dari 100 data, butuh 100 variabel! Solusinya: pakai List — cukup 1 variabel, bisa diakses pakai perulangan, ukurannya dinamis, dan algoritmanya jadi lebih ringkas.

Pertanyaan "apakah data X ada?" bisa dijawab lebih cepat kalau teknik penyimpanan datanya tepat:

Implementasi di Python

Built-in: list, dictionary, tuple, set. Untuk struktur data yang lebih kompleks (mis. Stack), kita bisa membuat Abstract Data Type (ADT) sendiri dengan OOP — mendefinisikan tipe data baru sesuai kebutuhan operasi.

2. Analisis Efisiensi Algoritma

Mengukur kinerja algoritma dari faktor waktu & ruang terhadap ukuran input — bukan dalam detik, tapi lewat growth rate.

Kriteria algoritma yang baik (kinerja)

  • Finite — langkahnya terbatas/berakhir
  • Efektif — menghasilkan jawaban yang benar
  • Efisien — pakai resources (waktu & memory) seminimal mungkin

Jumlah langkah ∝ waktu ∝ ukuran input — makin banyak data, makin banyak langkah & makin lama waktunya.

Dua cara analisis waktu

CaraPenjelasan
EmpirisJalankan program, ukur waktu nyata dengan input membesar, buat grafik, tentukan growth rate. Dipengaruhi hardware.
AsimtotikHitung dari source code: cari operasi dominan × berapa kali dieksekusi. Independen dari hardware.
Asumsi analisis asymptotic: random access machine — single-core processor, single RAM. Akses memory = O(1) per sel.

Best, worst, average case

Patokan yang dipakai selalu worst case — paling konsisten (sudah paling jelek, tidak mungkin lebih jelek lagi), dinyatakan dalam notasi Big-O. Best case cuma terjadi di kondisi tertentu; average case lebih realistis tapi lebih sulit dihitung.

Analisis asymptotic hanya melihat term terbesar, koefisien & term kecil diabaikan. Contoh: T(n) = 3n² + 2n + log n + ¼n → O(n²), dan T(n) = 0.3n³ + n → O(n³) (lebih buruk walau koefisiennya kecil).

Contoh per kategori

  • O(1) — ambil elemen pertama list, cek genap/ganjil, tukar 2 variabel
  • O(log n) — binary search, fast exponentiation (pangkat)
  • O(n) — jumlahkan semua elemen array, cari nilai maksimum
  • O(n log n) — merge sort, quick sort (avg), heap sort
  • O(n²) — bubble sort, cari pasangan dengan jumlah tertentu (nested loop)
  • O(2ⁿ) — Fibonacci rekursif, Menara Hanoi
  • O(n!) — permutasi, Traveling Salesman Problem brute-force

Studi kasus: cari jangkauan (range) data

Diberikan data = [19, 22, 17, 40, 28, 35, 14], cari selisih nilai tertinggi & terendah tanpa max()/min() bawaan Python (hasil: 40−14=26).

# Solusi 1 - nested loop
def jangkauan1(data):
    hasil = 0
    for i in range(len(data)):
        for j in range(len(data)):
            selisih = abs(data[i] - data[j])
            if selisih > hasil: hasil = selisih
    return hasil   # O(n^2)
# Solusi 2 - satu kali loop
def jangkauan2(data):
    high = low = data[0]
    for i in range(len(data)):
        if data[i] > high: high = data[i]
        if data[i] < low: low = data[i]
    return high - low   # O(n)

Hasil pengukuran empiris: pada n=10.000, Solusi 1 (O(n²)) butuh 22,3 detik, sedangkan Solusi 2 (O(n)) hanya 0,001 detik — bukti nyata kenapa Big-O penting, bukan cuma teori.

Contoh soal hitungan (wajib bisa!)

  • Soal: O(n²), n=1 juta → 9 detik. Berapa waktu untuk n=3 juta?
    Jawab: 9 × 3² = 81 detik
  • Soal: Algoritma O(n²) yang sama, berapa n maksimal supaya selesai dalam 60 detik?
    Jawab: 60 = 9×(nmax/1jt)² → nmax ≈ 2.582.000
  • Soal: Mana yang terbaik: T(n)=9.000.000n²+100.000.000, T(n)=10.000.000.000n+3.000.000.000.000, T(n)=4n³+2n²+5?
    Jawab: yang linear (n¹) — paling baik walau koefisiennya besar
  • Soal: A=O(n log n), B=O(n²), sama cepat di n=1.000. Mana lebih cepat di n=10.000?
    Jawab: O(n log n) lebih cepat (≈7,5× lebih cepat dari B)

Selection Sort

Array dibagi jadi 2 bagian: sorted & unsorted. Kombinasi searching + sorting.

1. Selectcari elemen terkecil di bagian unsorted
2. Swaptukar ke indeks awal unsorted
3. Shiftgeser 1 indeks batas unsorted
def SelectionSort(A):
    for i in range(len(A)):
        min_idx = i
        for j in range(i+1, len(A)):
            if A[min_idx] > A[j]:
                min_idx = j
        A[i], A[min_idx] = A[min_idx], A[i]

Bubble Sort

  1. Bandingkan sepasang item bersebelahan
  2. Swap jika tidak urut
  3. Ulang sampai akhir array — item terbesar akan berada di posisi terakhir
  4. Kembali ke langkah 1 dengan n−1 item
def bubbleSort(arr):
    n = len(arr)
    for i in range(n):
        for j in range(0, n-i-1):
            if arr[j] > arr[j+1]:
                arr[j], arr[j+1] = arr[j+1], arr[j]

Insertion Sort

Mirip cara orang mengurutkan kartu — ambil selembar, sisipkan ke tempat yang seharusnya. Elemen lain bergeser ke belakang.

  1. Mulai dengan 1 item yang dianggap sudah urut
  2. Ambil item berikutnya, sisipkan di posisi yang benar
  3. Ulangi sampai semua item dimasukkan
def insertionSort(arr):
    for i in range(1, len(arr)):
        key = arr[i]
        j = i-1
        while j >= 0 and key < arr[j]:
            arr[j+1] = arr[j]
            j -= 1
        arr[j+1] = key

Trace lengkap untuk data [5, 1, 10, 8, 7, 2]

Contoh soal langsung dari slide — jalankan ketiga algoritma pada data yang sama:

  • Bubble Sort — Pass 1: 5>1 tukar, 10>8 tukar, 10>7 tukar, 10>2 tukar → [1,5,8,7,2,10]. Berlanjut hingga Pass 5 → [1,2,5,7,8,10]
  • Selection Sort — Pass 1: terkecil = 1 (idx1), tukar dgn idx0 → [1,5,10,8,7,2]. Pass 2: terkecil = 2 (idx5), tukar dgn idx1 → [1,2,10,8,7,5]. Berlanjut → [1,2,5,7,8,10]
  • Insertion Sort — bagian urut awal [5]. Sisipkan 1 → [1,5,10,8,7,2]. Sisipkan 10 (tanpa geser). Sisipkan 8 → geser 10 → [1,5,8,10,7,2]. Berlanjut → [1,2,5,7,8,10]

Latihan (dari slide)

  • Urutkan 10, 15, 12, 18, 21, 29, 33, 42, 40, 45 descending pakai Selection Sort → butuh 5 kali swap
  • Urutkan 10, 15, 12, 18, 21, 29, 33 descending pakai Bubble Sort → butuh 6 pass
  • Kondisi terburuk (worst case) Insertion Sort adalah saat list sudah terurut terbalik — semua elemen harus digeser maksimal

4. Sorting Non Linear

Merge Sort & Quick Sort — dua algoritma sorting berbasis divide and conquer, jauh lebih cepat dari sorting linear untuk data besar.

Divide and Conquer

Paradigma memecahkan masalah dengan membaginya jadi sub-masalah lebih kecil sampai bisa langsung diselesaikan — biasanya diimplementasikan lewat fungsi rekursif.

Dividebagi masalah jadi bagian lebih kecil
Conquerselesaikan bagian terkecil (base case)
Combinegabungkan solusi jadi solusi utuh

Contoh lain algoritma divide and conquer di luar sorting:

AlgoritmaPeningkatan kompleksitas
Strassen matrix multiplicationO(n³) → O(n²·⁸)
Longest Common Prefix (LCP)"flower, flow, flawless" → "fl"
Exponential searchPencarian berbasis perkiraan rentang
Karatsuba multiplicationPerkalian besar: 4× jadi 3× operasi
Closest pair of pointsO(n²) → O(n log n)
Kelebihan: memecahkan masalah sulit, algoritma efisien, mendukung paralelisme.
Kekurangan: rekursi cenderung lambat (overhead function call); sub-problem bisa muncul berkali-kali → sebaiknya pakai Dynamic Programming (contoh: Fibonacci).

Contoh: cari max/min dengan Divide and Conquer

Data [15,24,13,12,17,10,14,11] dibagi 2 terus-menerus sampai base case (1 elemen / sepasang), lalu nilai max tiap bagian dibandingkan & digabung (combine) naik ke atas hingga ditemukan max keseluruhan = 24 (dan min = 10).

def cari_maksimum(data, kiri, kanan):
    if kiri == kanan:                      # base case
        return data[kiri]
    tengah = (kiri + kanan) // 2
    maksimum_kiri = cari_maksimum(data, kiri, tengah)
    maksimum_kanan = cari_maksimum(data, tengah + 1, kanan)
    if maksimum_kiri > maksimum_kanan:
        return maksimum_kiri
    else:
        return maksimum_kanan

Quick Sort

Ditemukan oleh C.A.R. Hoare pada tahun 1960, dimuat sebagai artikel di Computer Journal 5, April 1962.
  • Implementasi divide and conquer: Divide = Pivot, Conquer = Partition
  • Tidak stabil — partisi sering menukar elemen bernilai sama
  • In-place — tidak butuh memory tambahan

Pemilihan pivot: selalu elemen pertama, atau selalu elemen terakhir, atau random, atau elemen tengah (digeser ke kanan).

def quicksort(data, start, end):
    if start < end:
        pivot_index = partition(data, start, end)
        quicksort(data, start, pivot_index-1)
        quicksort(data, pivot_index+1, end)

def partition(data, start, end):
    pivot = data[end]          # pivot = elemen terakhir
    left, right = start, end - 1
    while left <= right:
        while data[left] < pivot: left += 1
        while data[right] > pivot: right -= 1
        if left <= right:
            data[left], data[right] = data[right], data[left]
            left += 1; right -= 1
    data[left], data[end] = data[end], data[left]
    return left

Kinerja: Worst case O(n²) — pivot selalu nilai tertinggi/terendah (mis. data sudah urut tapi ingin diurutkan sebaliknya). Best case O(n log n) — pivot selalu nilai median.

Merge Sort

Ditemukan oleh John von Neumann pada tahun 1945 — salah satu algoritma divide and conquer paling awal di era komputasi modern.
  • Divide = bagi data jadi 2 bagian sampai 1 elemen; Conquer = gabungkan (merge) elemen secara terurut
  • Stable — urutan data bernilai sama tidak berubah
  • Bukan in-place — butuh memory tambahan untuk potongan data & hasil merge

4 tahapan Merge Sort

  1. Tentukan titik tengah, bagi data jadi kiri & kanan
  2. Merge sort bagian kiri (rekursif)
  3. Merge sort bagian kanan (rekursif)
  4. Gabungkan (merge) hasil kiri & kanan secara terurut
def mergesort(data):
    if len(data) > 1:
        mid = len(data) // 2
        left, right = data[:mid], data[mid:]
        mergesort(left); mergesort(right)
        i = j = k = 0
        while i < len(left) and j < len(right):
            if left[i] <= right[j]:
                data[k] = left[i]; i += 1
            else:
                data[k] = right[j]; j += 1
            k += 1
        while i < len(left):  data[k]=left[i];  i+=1; k+=1
        while j < len(right): data[k]=right[j]; j+=1; k+=1

Contoh proses divide & merge (data [15,24,13,12,17,10,14,16])

Divide: [15,24,13,12,17,10,14,16] → [15,24,13,12] | [17,10,14,16] → ... → dipecah sampai elemen tunggal.

Merge naik bertahap: [15]&[24]→[15,24] · [13]&[12]→[12,13] · [17]&[10]→[10,17] · [14]&[16]→[14,16] → lalu [15,24]&[12,13]→[12,13,15,24] · [10,17]&[14,16]→[10,14,16,17] → akhirnya digabung jadi [10,12,13,14,15,16,17,24].

Kinerja: selalu O(n log n) di best, worst, maupun average case — karena prosesnya selalu sama (bagi dua, lalu merge), tidak dipengaruhi urutan data awal.

1. Searching (Pencarian)

Pencarian data pada list: apakah nilai X ada atau tidak?

Inti yang wajib diingat
  • Searching = pencarian data dengan menelusuri data (retrieval information). Pada materi ini hanya menjawab ADA / TIDAK ADA.
  • Sequential Search → satu-satunya yang bisa dipakai pada list belum terurut · O(n)
  • Binary Search → syarat list sudah terurut, data dibagi 2 tiap langkah · O(log n)
  • Exponential Search → lipat dua indeks (1, 2, 4, 8, …) untuk cari rentang, lalu binary search · best O(1), avg/worst O(log i)

Dasar searching

  • Pada suatu data sering dibutuhkan pembacaan kembali informasi (retrieval information) lewat searching.
  • Tempat pencarian: array/list di memori, atau file di external storage.
  • Bentuk pencarian: (1) apakah data bernilai x ada di List? (2) ada berapa data bernilai x? (3) pada posisi berapa saja data bernilai x?
  • Dibahas: collection berupa sequence (List), dengan dua kondisi list: belum terurut & sudah terurut.

Sequential Search (Linear Search)

Menelusuri data satu per satu dari awal sampai ketemu atau data habis. Contoh data: [8, 10, 6, -2, 11, 7, 1, 100], cari 6 → tampil “ADA”; kalau tidak ada tampil “TIDAK ADA”.

def seqSearch(arr, x):
    for i in range(len(arr)):
        if arr[i] == x:
            return 1      # ADA
    return 0              # TIDAK ADA
Catatan: kode di slide memakai range(len(arr)+1) (bikin IndexError) dan tidak ada return untuk kasus tidak ketemu — versi di atas yang benar.

Kompleksitas: best O(1) (ada di indeks awal), worst O(n) (ada di akhir / tidak ada).

Binary Search

Teknik pencarian dengan membagi data menjadi dua bagian setiap proses. Data harus diurutkan lebih dulu berdasarkan kunci pencarian.

Karakteristik penting

  • Input array sudah sorted
  • Pencarian pada subarray tempat item x mungkin berada
  • Berulang kali membandingkan x dengan elemen tengah m:
    • jika x == m → ketemu!
    • jika x > m → cari di posisi setelah m (low = mid + 1)
    • jika x < m → cari di posisi sebelum m (high = mid − 1)

# Iteratif
def binary_search(list, item):
    low = 0
    high = len(list) - 1
    while low <= high:
        mid = (low + high) // 2
        guess = list[mid]
        if guess == item:
            return mid
        if guess > item:
            high = mid - 1
        else:
            low = mid + 1
    return -1
# Rekursif (contoh kode)
def binary_search_rec(arr, item, low, high):
    if low > high:
        return -1
    mid = (low + high) // 2
    if arr[mid] == item:
        return mid
    elif arr[mid] > item:
        return binary_search_rec(arr, item, low, mid - 1)
    else:
        return binary_search_rec(arr, item, mid + 1, high)

Exponential Search

Disebut juga doubling search / galloping search. Algoritma untuk menemukan target pada list terurut. Sangat efisien untuk data terurut berukuran sangat besar (unbounded / infinite array) karena batas akhir list tidak perlu diketahui di awal.

Dua tahap utama

Tahap 1 — cari rentanglipat gandakan indeks secara eksponensial: 1, 2, 4, 8, …, 2k
Tahap 2 — binary searchjalankan binary search pada rentang [low, high] yang ditemukan

Langkah kerja

  1. Periksa indeks 0. Kalau cocok dengan target → selesai.
  2. Tetapkan i = 1.
  3. Kalikan i = i × 2 selama i < n dan A[i] < target.
  4. Tentukan interval: low = i/2, high = min(i, n−1).
  5. Jalankan binary search standar di dalam [low, high].
def exponential_search(arr, target):
    if arr[0] == target: return 0
    n = len(arr); bound = 1
    while bound < n and arr[bound] < target:
        bound *= 2                         # batas x 2
    left, right = bound//2, min(bound, n-1)
    while left <= right:                   # binary search
        mid = (left + right) // 2
        if arr[mid] == target: return mid
        elif arr[mid] < target: left = mid + 1
        else: right = mid - 1
    return -1

Kompleksitas: best O(1) (target di indeks awal) · average & worst O(log i), i = posisi indeks elemen yang dicari.

2. Hashing

Cara menemukan data langsung lewat index yang dihitung dari key — tanpa membandingkan satu per satu.

Inti yang wajib diingat
  • Hash table = data disimpan di array; index = fungsi hash(key) → pencarian O(1) (direct access).
  • Fungsi hash yang bagus: cepat · deterministic · fixed-length · evenly distribution. Sifatnya satu arah.
  • Collision = dua key berbeda menghasilkan index yang sama → masalah utama hash table.
  • Load factor = 100% × (jumlah data / kapasitas tabel) → makin besar, makin sering collision.
  • Penanganan collision: Open Addressing (Linear Probing, Quadratic Probing, Double Hashing) dan Open Hashing (Separate Chaining).
  • Kegunaan: dictionary, representasi object, database indexing, caches.

Review: Dictionary & hash table

Di Python, Dictionary menyimpan pasangan key-value; value diakses lewat key. Aksesnya sangat cepat karena implementasinya berdasarkan hash table.

data = {71:'Informatika', 72:'Sistem Informasi', 41:'Kedokteran', 11:'Manajemen'}
data[71]   # 'Informatika'
  • Nilai disimpan dalam list/array yang diakses lewat index-nya.
  • Linear & binary search harus mencari karena tidak tahu index data. Kalau index diketahui, akses jauh lebih cepat.
  • Cara tahu index butuh dua hal: key + fungsi hash → masukkan key ke fungsi hash untuk mendapat index.

Kenapa pakai hashing?

Linear & binary search adalah comparison-based search — big-O terbaik yang bisa dicapai hanya O(log n). Hashing memakai direct access sehingga pencarian bisa O(1).

Fungsi hash

Contoh: f(key) = key mod 7. Untuk key 71: f(71) = 71 mod 7 = 1 → 'Informatika' disimpan di index ke-1.

Index0123456

  • Fungsi hash memetakan nilai data (panjang/besar bervariasi) ke nilai dalam rentang tetap (fixed).
  • Merupakan fungsi satu arah: dari key bisa didapat value/lokasi, tetapi tidak sebaliknya.

Ciri fungsi hash yang bagus

  • Proses perhitungan cepat
  • Deterministic — key yang sama harus menghasilkan nilai hash yang sama
  • Fixed-length value — hasil dalam rentang yang telah ditentukan
  • Evenly distribution — key menyebar merata, tidak mengumpul di satu tempat
  • Perfect hash function — hanya mungkin jika seluruh key sudah diketahui sebelumnya

Permasalahan fungsi hash

  • Harapan: Simple Uniform Hashing — tiap key punya peluang sama menempati salah satu slot, hasil tidak mengumpul di satu area.
  • Contoh buruk: f(key) = key mod 7 → key 9, 16, 37, 2 semuanya menghasilkan index 2.
  • Space problem: kalau f(key) = key (71 di index 71, 72 di index 72…), butuh space sangat besar dan banyak tempat kosong → tidak efisien.
  • Mengatasi collision harus cepat & efisien. Kalau waktu tidak masalah, cukup linear probing — tapi butuh space besar.

Linear Probing

Melakukan perhitungan kembali (probing) untuk menemukan slot kosong, secara sekuensial mulai dari posisi collision (selisih 1).

Rumus: Slot = ( h(key) + i ) % M
M = jumlah slot hash table · i = langkah probe (biasanya bertambah 1) · h(key) = nilai hash awal
  • Menambah 226: h = 226 mod 13 = 5 → bentrok dengan 96 → probe ke slot 6 (kosong) → simpan.
  • Ujung tabel: bila probing mencapai slot terakhir, lanjut dari slot pertama; ulangi sampai semua slot diperiksa (contoh 388 → hash 11 → 11, 12 penuh → slot 0).
  • Searching: hitung hash target, cek key == target; bila belum, lanjut probing sampai semua slot diperiksa atau ketemu slot kosong (contoh 903 → ada; 561 → tidak ada).
  • Deletion: pakai flag khusus untuk menandai slot yang pernah dipakai. Tanpa flag, setelah 226 dihapus slot 6 jadi kosong dan pencarian 903 berhenti terlalu cepat (salah “tidak ada”).

Quadratic Probing

Kalau linear probing mencari tempat sebelah (selisih 1), quadratic probing mencari berdasarkan jarak kuadrat — “melompat” lebih jauh sehingga lebih mudah menemukan slot kosong.

Rumus: slot = ( home + i² ) % M
Urutan probe: hash(key) → (hash + 1) % M → (hash + 4) % M → (hash + 9) % M → (hash + 16) % M …

Contoh (hash(k) = k mod 7, tabel berisi 18 di idx 4): tambah 3 → idx 3 (kosong). Tambah 38 → hash 3 penuh → +1 (idx 4 penuh) → +4 (idx 0 kosong) → simpan di idx 0.

Double Hashing

Menyiapkan dua fungsi hash sekaligus: kalau fungsi pertama collision, lokasi baru dihitung dengan fungsi hash kedua. Kalau fungsi kedua juga collision → pakai linear atau quadratic probing.

Urutan probe: hash(key) → (hash(key) + hp(key)) % m → (hash(key) + 2 × hp(key)) % m → (hash(key) + 3 × hp(key)) % m …
hp() = fungsi hash kedua, menentukan banyaknya slot yang dilompati tiap collision (tergantung key).
  • Contoh (hash = k mod 7, hp = k mod 5): tambah 21 → hash 0 penuh, hp = 1 → idx 1.
  • Tambah 4 → hash 4 penuh, hp = 4 → probe 4, 8 (idx 1 penuh), 12 (idx 5 kosong) → simpan di idx 5.
  • Tambah 35 → hash 0 penuh, hp(35) = 0 → probe 0, 0, 0, … tidak pernah pindah → tidak baik! (hp tidak boleh menghasilkan 0).

  • Implementasi Dictionary — di bahasa lain disebut Associative Array
  • Representasi Object pada bahasa dinamis yang mendukung OOP: Perl, Python, JavaScript, Ruby

3. ADT dan OOP

Dari pemrograman prosedural ke berorientasi obyek: class, object, atribut, method, dan konsep dasar OOP.

Inti yang wajib diingat
  • Class = blueprint/template berisi nama class, daftar atribut, daftar method. Object = hasil instansiasi dari class.
  • Atribut (data member / property / state) = data object. Method (function / behaviour) = kemampuan object.
  • Constructor = def __init__(self, …), dipanggil otomatis saat objek dibuat untuk inisialisasi atribut.
  • 4 konsep dasar OOP: Abstraction · Encapsulation · Inheritance · Polymorphism.
  • Accessor/getter = hanya membaca; Mutator/setter = mengubah nilai atribut.
  • self = menunjuk object/class yang bersangkutan.

Linked List (Materi 07)

Struktur data linier & dinamis yang menyambung node satu ke node berikutnya lewat pointer / konektor.

Pengertian & ciri-ciri

  • Linier: data tersusun berurutan (satu node → node berikutnya).
  • Dinamis: jumlah data bisa membesar/mengecil sesuai kebutuhan.
  • Tiap node = data + konektor (Single: next; Double: next & prev).
  • Letak di memory tidak contiguous (array: contiguous / berurutan).
  • Head wajib ada (node paling depan); tail opsional (node paling belakang).
  • Non-circular: node terakhir bernilai None. Akses sequential, bukan random access.

Manfaat / alasan memakai Linked List

  • Data & jumlah data dinamis.
  • Insert & hapus lebih mudah daripada array (array harus menggeser data).
  • Efisien memory, karena ukuran menyesuaikan kebutuhan.
  • Dasar untuk Stack, Queue, Deque, playlist, dll.
Kelemahan: butuh memory ekstra untuk konektor; tidak bisa random access; Single sulit traversing mundur; Double bisa mundur tapi memory lebih besar lagi.

Wajib diingat
    
    
      
  • Linked list = sequential access, dinamis, memory tidak contiguous, butuh memory ekstra untuk konektor.
    • 
      
  • Insert: sambungkan node baru ke node berikutnya DULU, baru geser head / sambung dari node sebelumnya, supaya konektor tidak putus.
    • 
      
  • Jangan sembarangan menggeser head & tail; traversing pakai helper.
    • 
      
  • Insert mid: posisi 0 = insert head, ≥ size = insert tail; helper berhenti di posisi − 1.
    • 
      
  • Delete: 3 kasus (head, tail, tengah) + kasus size = 1 (list jadi kosong).
    • 
      
  • Delete tail Single O(n), Double O(1). Circular: tail.next = head harus selalu terjaga, awas infinite loop.
