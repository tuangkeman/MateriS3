Empat kriteria evaluasi algoritma

  • Completeness: pasti menemukan solusi bila ada?
  • Optimality: solusi yang ditemukan berbiaya terendah?
  • Time complexity: jumlah node yang dibangkitkan.
  • Space complexity: jumlah node maksimum di memori.

Istilah penting: frontier (node dibangkitkan, belum di-expand), explored/visited set (mencegah siklus), tree search vs graph search (graph search mengingat state yang sudah dikunjungi).

Satu kerangka, banyak algoritma

Ruang keadaan (state space) adalah graf: node = state, sisi = aksi. Seluruh algoritma di halaman 2 memakai kerangka berikut, perbedaannya hanya pada cara memilih node dari frontier:

function SEARCH(problem, order):
  frontier = [start];  explored = {}
  while frontier tidak kosong:
    n = frontier.pop_by(order)     # SATU-SATUNYA bagian yang berbeda
    if goal(n): return path(n)
    explored.add(n)
    for m in successors(n):
      if m tidak di explored/frontier: frontier.add(m)

Tree search vs graph search: tree search tidak mengingat state yang sudah dikunjungi sehingga bisa mengulang state yang sama (atau berputar tanpa henti pada graf bersiklus). 1F. Fungsi Heuristik h(n)

Heuristik h(n) adalah estimasi biaya termurah dari state n ke goal. Tiga besaran yang harus dibedakan: g(n) = biaya nyata dari start ke n (sudah dibayar), h(n) = perkiraan sisa biaya (belum pasti), f(n) = g(n) + h(n) = perkiraan total biaya solusi lewat n. UCS memakai g saja, Greedy memakai h saja, A* memakai f.

  • Admissible: h(n) ≤ biaya nyata terendah dari n ke goal, h*(n). Menjamin A* tree search optimal.
  • Consistent (monotonic): h(n) ≤ c(n,n′) + h(n′). Nilai f tidak pernah turun sepanjang jalur → A* graph search optimal tanpa perlu membuka ulang node.
  • Dominance: jika h2(n) ≥ h1(n) untuk semua n dan keduanya admissible, h2 lebih baik (lebih sedikit node di-expand).
  • Relaxed problem: heuristik umumnya diperoleh dengan melonggarkan aturan masalah.
MasalahHeuristikAdmissible?
Grid 4 arahJarak Manhattan |Δr|+|Δc|Ya (biaya minimum per langkah = 1)
Grid 8 arahJarak Euclid / ChebyshevYa
8-puzzleh1 = jumlah ubin salah tempat; h2 = jumlah jarak Manhattan semua ubinYa; h2 mendominasi h1
Grid 4 arah2 × ManhattanTidak (melebih-lebihkan) → A* bisa tidak optimal

Efek kualitas heuristik pada A*

  • h(n) = 0 (tanpa informasi): A* berubah menjadi UCS.
  • h admissible & semakin mendekati h*: node yang dibuka semakin sedikit, solusi tetap optimal.
  • h = h* (sempurna): A* langsung menuju goal tanpa expand node yang salah.
  • h melebih-lebihkan (tidak admissible): cepat tetapi optimalitas hilang. Jika h dipakai sendirian, itulah Greedy.
  • Cara membuat heuristik: longgarkan aturan masalah (relaxed problem). Contoh: ubin 8-puzzle boleh "melompat" ⇒ misplaced tiles; ubin boleh bergerak menembus ubin lain ⇒ Manhattan.

Uninformed Search · Pathfinding

BFS — Breadth-First Search
Intuisi

Seperti riak air: semua node pada kedalaman d diperiksa sebelum kedalaman d+1. Frontier berupa queue FIFO, sehingga node yang paling dangkal selalu keluar lebih dulu.

Pseudocode
queue = [start]; visited = {start}
while queue:
  n = queue.pop_front()
  if goal(n): return path(n)
  for m in succ(n):
    if m not in visited: visited.add(m); queue.push_back(m)
Kelebihan & Kekurangan

+ Complete & menemukan solusi dengan jumlah langkah paling sedikit. − Memori O(b^d) sangat boros (semua frontier disimpan); mengabaikan bobot biaya.

Kasus penggunaan yang cocok

Graf tanpa bobot / biaya tiap langkah sama: jalur terpendek labirin, derajat pertemanan (six degrees), crawler level dangkal, puzzle dengan solusi dangkal.

⚠ Jebakan UTS: BFS optimal hanya untuk biaya langkah seragam. Pada graf berbobot, BFS bisa memberi jalur "paling sedikit langkah" yang ternyata mahal (lihat contoh trace 2C di halaman ini).
DFS — Depth-First Search
Intuisi

Seperti menelusuri lorong sampai buntu, baru backtrack. Frontier berupa stack LIFO (atau rekursi), sehingga node terdalam yang terakhir ditambahkan diproses lebih dulu.

Pseudocode
stack = [start]
while stack:
  n = stack.pop()
  if goal(n): return path(n)
  if n not in visited:
    visited.add(n)
    for m in succ(n): stack.push(m)
Kelebihan & Kekurangan

+ Memori hanya O(b·m); cepat jika solusi dalam dan banyak. − Tidak optimal; tidak complete bila ada siklus (tanpa visited set) atau ruang tak hingga; waktu O(b^m) bisa buruk bila m ≫ d.

Kasus penggunaan yang cocok

Puzzle/CSP (Sudoku, N-Queens via backtracking), deteksi siklus, topological sort, saat memori sangat terbatas dan solusi apa saja sudah cukup.

⚠ Jebakan UTS: Jawaban "DFS complete?" = Tidak pada ruang tak hingga/siklus tanpa pelacakan visited; pada graf berhingga dengan visited set ia complete. Sebutkan syaratnya.
UCS — Uniform Cost Search
Intuisi

BFS yang sadar biaya: selalu expand node dengan g(n) terkecil (biaya kumulatif dari start). Frontier berupa priority queue berdasarkan g(n). Setara algoritma Dijkstra.

Pseudocode
pq = [(0,start)]; best = {start:0}
while pq:
  g,n = pq.pop_min()
  if goal(n): return path(n), g   # tes goal SAAT EXPAND
  for m,c in succ(n):
    if g+c < best.get(m,inf):
      best[m]=g+c; pq.push((g+c,m))
Kelebihan & Kekurangan

+ Complete & optimal selama biaya langkah ≥ ε > 0. − Menjelajah ke segala arah (tanpa petunjuk tujuan) sehingga boros; kompleksitas O(b^(1+⌊C*/ε⌋)).

Kasus penggunaan yang cocok

Rute dengan jarak/tol/waktu berbeda, routing jaringan (OSPF), bila tidak ada heuristik yang andal tetapi biaya bervariasi.

⚠ Jebakan UTS: Tes goal dilakukan saat node di-expand, bukan saat di-generate. Jika dites saat generate, UCS bisa mengembalikan jalur tidak optimal. Biaya nol/negatif merusak jaminan optimal.
DLS & IDS — Depth-Limited & Iterative Deepening
Intuisi

DLS = DFS yang dilarang melewati kedalaman l (node di kedalaman l dianggap tanpa anak). IDS menjalankan DLS dengan l=0,1,2,… hingga goal ditemukan: urutan penemuan seperti BFS, memori seperti DFS.

Pseudocode
for l = 0,1,2,...:
  r = DLS(start, l)
  if r != cutoff: return r
# DLS mengembalikan: solusi | cutoff | failure
Kelebihan & Kekurangan

+ DLS: memori O(b·l), mencegah jalan tak hingga; − tidak complete bila l < d, tidak optimal bila l > d. IDS: complete, optimal (biaya seragam), memori O(b·d); − node level atas dikunjungi berulang (tetapi overhead kecil karena sebagian besar node ada di level terdalam: total tetap O(b^d)).

Kasus penggunaan yang cocok

DLS: pohon game/permainan dengan batas langkah, direktori dengan batas subfolder. IDS: metode uninformed default saat ruang sangat besar, kedalaman solusi tidak diketahui, memori terbatas (mis. catur, puzzle besar).

⚠ Jebakan UTS: Bedakan hasil cutoff (batas tercapai, mungkin masih ada solusi) vs failure (seluruh ruang habis, pasti tidak ada solusi). Banyak soal menanyakan alasan IDS "tidak boros" meski mengulang.

Informed Search · Pathfinding

Best-First Search (kerangka umum)
Intuisi

Best-First Search (BestFS; jangan tertukar dengan Breadth-First Search) adalah kerangka umum: selalu expand node di frontier dengan nilai fungsi evaluasi f(n) terkecil, memakai priority queue. Algoritmanya sama untuk semua; yang berbeda hanya definisi f(n). Karena itu UCS, Greedy, dan A* semuanya adalah kasus khusus Best-First Search.

Pseudocode
pq = [(f(start), start)]; best_g = {start: 0}
while pq:
  _, n = pq.pop_min()              # f(n) terkecil
  if goal(n): return path(n)
  for m, c in succ(n):
    g_new = g[n] + c
    if g_new < best_g.get(m, inf):
      best_g[m] = g_new
      pq.push((f(m), m))           # f bergantung pada pilihan
Pilihan f(n)MenjadiCompleteOptimal
f = g(n)Uniform Cost SearchYaYa
f = h(n)Greedy Best-First SearchTidak*Tidak
f = g(n) + h(n)A*YaYa (h admissible/consistent)
f = g(n) + w·h(n), w > 1Weighted A*YaTidak, tetapi biaya ≤ w × optimal jika h admissible
f = kedalaman nodeBFS (Breadth-First)YaYa (biaya seragam)
Kelebihan & Kekurangan

+ Satu kerangka menjelaskan banyak algoritma; mudah membuat variasi baru hanya dengan mengganti f(n). − Sifat completeness, optimality, dan kompleksitas tidak bisa dinyatakan tanpa menyebut f(n); memori bisa eksponensial karena menyimpan seluruh frontier. *Complete pada ruang berhingga jika memakai explored set.

Kasus penggunaan yang cocok

Sebagai dasar merancang pencarian sendiri: pilih f sesuai kebutuhan (hanya cepat → h; optimal → g+h; cepat dengan toleransi biaya → weighted A*). Dalam praktik, istilah "Best-First Search" sering dipakai untuk Greedy; selalu periksa f(n)-nya.

⚠ Jebakan UTS: Best-First Search bukan satu algoritma dengan satu jawaban "optimal atau tidak". Jika soal menyebut f(n) = h(n) maka itu Greedy (tidak optimal); jika f(n) = g(n) + h(n) maka itu A*. Bedakan juga dari Breadth-First Search yang sama-sama disingkat BFS.
Greedy Best-First Search
Intuisi

Rakus: expand node dengan h(n) terkecil (tampak paling dekat goal), mengabaikan biaya yang sudah dikeluarkan. f(n) = h(n).

Pseudocode
pq = [(h(start),start)]
while pq:
  _,n = pq.pop_min()
  if goal(n): return path(n)
  for m in succ(n):
    if m not in visited: pq.push((h(m),m))
Kelebihan & Kekurangan

+ Sangat cepat bila heuristik bagus, memori kecil dalam praktik. − Tidak optimal, tidak complete (bisa terjebak loop tanpa visited); worst case O(b^m).

Kasus penggunaan yang cocok

Waktu komputasi sangat ketat dan jalur "cukup baik" diterima: navigasi kasar, pencarian dokumen berdasar skor kemiripan.

⚠ Jebakan UTS: Greedy terjebak "jebakan U" (dead-end yang tampak dekat goal). Lihat contoh trace: Greedy memilih A karena h kecil, padahal total biayanya lebih mahal.
A* — A-Star Search
Intuisi

Menggabungkan sisi UCS dan Greedy: f(n) = g(n) + h(n). g = biaya nyata sejauh ini, h = estimasi sisa biaya. Node dipilih berdasarkan estimasi total biaya solusi melalui n.

Pseudocode
pq = [(h(start),start)]; g = {start:0}
while pq:
  f,n = pq.pop_min()
  if goal(n): return path(n), g[n]
  for m,c in succ(n):
    if g[n]+c < g.get(m,inf):
      g[m]=g[n]+c; pq.push((g[m]+h(m), m))
Kelebihan & Kekurangan

+ Complete & optimal jika h admissible (tree search) / consistent (graph search); sangat efisien dengan h yang informatif. − Memori O(b^d): semua node frontier disimpan. h=0 → UCS; h sempurna → langsung ke goal.

Kasus penggunaan yang cocok

GPS/peta, NPC game, perencanaan gerak robot, 8-puzzle (heuristik Manhattan/misplaced tiles).

⚠ Jebakan UTS: Admissible: h(n) ≤ h*(n) (tidak pernah melebih-lebihkan). Consistent: h(n) ≤ c(n,n′) + h(n′) — consistent ⇒ admissible, tidak sebaliknya. Heuristik yang mendominasi (h2 ≥ h1, keduanya admissible) memperluas lebih sedikit node.

Informed Search · Local Search

Hill Climbing (Local Search)
Intuisi

Hanya menyimpan satu state saat ini, lalu pindah ke tetangga yang lebih baik menurut fungsi objektif. Tidak menyimpan jalur: yang dicari adalah state akhir yang bagus, bukan rute.

Pseudocode
cur = initial
loop:
  nb = best_neighbor(cur)      # steepest ascent
  if value(nb) <= value(cur): return cur
  cur = nb
Kelebihan & Kekurangan

+ Memori O(1), sangat cepat, cocok ruang besar. − Terjebak local maximum, plateau (datar), dan ridge (punggung bukit); tidak complete/optimal.

Kasus penggunaan yang cocok

Optimasi (penjadwalan kuliah, N-Queens, desain sirkuit, tuning parameter) di mana jalur tidak penting. Varian: simple (tetangga pertama yang lebih baik), steepest-ascent (terbaik), stochastic (acak di antara yang lebih baik), random-restart (mulai ulang dari banyak titik awal → mengatasi local optimum).

⚠ Jebakan UTS: Hill Climbing bukan algoritma "jalur terpendek". Pada grid di simulator, ia berhenti ketika tertahan dinding (local optimum) meski goal ada: coba tempatkan dinding berbentuk "U".
Hill Climbing Random Restart
Intuisi

Hill Climbing biasa hanya sekali mendaki: jika terjebak di puncak lokal ia berhenti. Random Restart membungkusnya dengan loop luar: mulai ulang dari state awal acak, mendaki lagi, dan simpan hasil terbaik / hentikan bila goal tercapai. Analogi: pendaki yang terjebak bukit kecil lalu dijatuhkan helikopter di titik acak untuk mencoba lagi.

Pseudocode
best = None
for i = 0 .. MAX_RESTART:
  cur = (i == 0) ? initial : random_state()
  loop:                              # steepest-ascent
    nb = best_neighbor(cur)
    if value(nb) <= value(cur): break
    cur = nb
  if goal(cur): return cur
  if value(cur) > value(best): best = cur
return best
Kelebihan & Kekurangan

+ Mengatasi local maximum, plateau, dan ridge tanpa mengubah aturan dasar HC; memori tetap O(1); probabilistically complete: bila satu pendakian berhasil dengan peluang p, jumlah restart yang diharapkan sekitar 1/p, sehingga peluang sukses mendekati 1 untuk restart tak terbatas. − Tidak ada jaminan optimal dalam jumlah restart terbatas; hasil tidak deterministik; sia-sia bila ruang punya sangat banyak puncak lokal (peluang p kecil) atau bila state acak sulit dibangkitkan; jalur tidak disimpan.

Kasus penggunaan yang cocok

Optimasi di ruang besar dengan banyak optimum lokal dan evaluasi murah: N-Queens (kasus 8-Queens: HC biasa hanya sukses sekitar 14% pendakian, random restart hampir pasti sukses dalam sekitar 7 restart), penjadwalan, desain sirkuit, tuning parameter.

⚠ Jebakan UTS: Random restart bukan algoritma baru yang melihat lebih jauh; ia hanya mengulang HC. Complete-nya bersifat probabilistik, bukan pasti. Bandingkan dengan Simulated Annealing yang mengatasi local optimum dengan menerima langkah turun secara acak dalam satu pendakian.
Simulated Annealing
Intuisi

Terinspirasi proses annealing logam: dipanaskan lalu didinginkan perlahan agar strukturnya rapi. Pada suhu tinggi algoritma berani menerima langkah yang lebih buruk sehingga bisa keluar dari local optimum; seiring suhu T turun, ia makin selektif dan akhirnya berperilaku seperti Hill Climbing.

Pseudocode
cur = initial;  T = T0
while T > T_min:
  nb = random_neighbor(cur)
  delta = value(nb) - value(cur)      # maksimasi
  if delta > 0 or random() < exp(delta / T):
    cur = nb
  T = alpha * T                       # mis. alpha = 0.99
Kelebihan & Kekurangan

+ Memori O(1); dapat lolos dari local optimum dalam satu kali jalan; dengan jadwal pendinginan yang cukup lambat secara teori konvergen ke optimum global. − Hasil tidak deterministik; kualitas sangat bergantung pada jadwal suhu (T0, α) yang harus ditala; jadwal yang menjamin optimum global terlalu lambat untuk praktik.

Kasus penggunaan yang cocok

Optimasi kombinatorial dengan banyak optimum lokal: penjadwalan, tata letak sirkuit (VLSI), Traveling Salesman Problem, pengaturan parameter.

⚠ Jebakan UTS: Peluang menerima langkah buruk adalah e^(Δ/T) (Δ negatif pada maksimasi): makin besar kerugian dan makin rendah T, makin kecil peluangnya. T tinggi ≈ random walk, T → 0 ≈ Hill Climbing. SA adalah satu pendakian yang boleh turun, berbeda dari Random Restart yang mengulang banyak pendakian.
Local Beam Search
Intuisi

Menyimpan k state sekaligus, bukan satu. Tiap iterasi, semua successor dari k state dikumpulkan ke satu kumpulan, lalu hanya k terbaik yang dipertahankan. Informasi dibagikan antar beam: jika satu beam menemukan area bagus, beam lain ikut pindah ke sana.

Pseudocode
beam = k_random_states()
loop:
  if any(goal(s) for s in beam): return s
  cands = all successors of every s in beam
  beam = k best of cands by value / h
Kelebihan & Kekurangan

+ Memori O(k); eksplorasi lebih luas daripada Hill Climbing; k=1 sama dengan Hill Climbing. − Beam cepat kehilangan keragaman karena semua beam berkumpul di satu area (varian stochastic beam search memilih secara acak berbobot nilai); tidak complete dan tidak optimal.

Kasus penggunaan yang cocok

Ruang pencarian sangat besar yang tidak muat untuk BFS/A*: penerjemahan mesin dan pengenalan suara (beam search pada decoding), penyusunan kalimat pada pipeline Bahasa Isyarat (halaman 6).

⚠ Jebakan UTS: Local beam search bukan k Hill Climbing yang berjalan paralel dan independen. Pada beam search, successor semua beam digabung dan dipilih k terbaik secara global, sehingga satu beam dapat "mengambil alih" slot beam lainnya.
Genetic Algorithm (GA)
Intuisi

Mencari solusi dengan meniru evolusi: mempertahankan populasi kandidat solusi (kromosom), memberi nilai fitness, memilih yang bagus sebagai orang tua, mengawinkannya (crossover), dan sesekali mengubah acak (mutation). Generasi demi generasi populasi bergeser ke area fitness tinggi.

Pseudocode
pop = random_population(N)
repeat G generasi:
  evaluasi fitness(pop)
  next = [elit terbaik]
  while |next| < N:
    p1, p2 = select(pop)        # roulette / tournament
    c = crossover(p1, p2)       # prob. pc
    c = mutate(c)               # prob. pm per gen
    next.append(c)
  pop = next
return individu terbaik
Kelebihan & Kekurangan

+ Tidak butuh gradien atau heuristik arah; mencari di banyak titik sekaligus; cocok untuk ruang multimodal dan diskret. − Banyak parameter (ukuran populasi, pc, pm) yang harus ditala; evaluasi fitness mahal karena dilakukan untuk seluruh populasi; dapat premature convergence (populasi seragam terlalu cepat); tidak ada jaminan optimum.

Kasus penggunaan yang cocok

Optimasi desain (antena, bentuk sayap), penjadwalan kompleks, pemilihan fitur dan tuning hyperparameter model ML (terkait 6C), N-Queens.

⚠ Jebakan UTS: Hafalkan lima komponen: representasi kromosom, fungsi fitness, seleksi, crossover, mutasi (ditambah elitisme). Crossover menggabungkan sifat dua induk (eksploitasi), mutasi menjaga keragaman (eksplorasi). Tanpa mutasi populasi bisa macet di optimum lokal.
Minimax
Intuisi

Untuk permainan dua pemain bergiliran dengan lawan yang bermain optimal. Pemain MAX memilih langkah yang memaksimalkan nilai, pemain MIN (lawan) memilih yang meminimalkan. Nilai tiap node dihitung dari bawah: daun dinilai fungsi utilitas (atau fungsi evaluasi bila dipotong di kedalaman tertentu), lalu dirambatkan ke atas.

Pseudocode
function MINIMAX(s, depth, isMax):
  if terminal(s) or depth == 0: return eval(s)
  if isMax: return max(MINIMAX(c, depth-1, false) for c in succ(s))
  else:     return min(MINIMAX(c, depth-1, true)  for c in succ(s))
Kelebihan & Kekurangan

+ Complete pada pohon berhingga dan optimal terhadap lawan yang optimal; sederhana. − Waktu O(b^m) dan memori O(b·m) (DFS); ledakan pada permainan besar (catur b≈35); mutu hasil bergantung pada fungsi evaluasi saat dipotong.

Kasus penggunaan yang cocok

Tic-tac-toe, catur, dam, Connect Four, dan permainan zero-sum informasi sempurna lainnya.

⚠ Jebakan UTS: Minimax mengasumsikan lawan selalu memilih langkah terbaik untuknya, jadi hasilnya adalah jaminan kasus terburuk. Ia bukan pencarian jalur: yang dikeluarkan adalah satu langkah terbaik untuk giliran sekarang.
Alpha-Beta Pruning
Intuisi

Minimax yang membuang cabang yang tidak mungkin memengaruhi keputusan akhir. α = nilai terbaik yang sudah dijamin untuk MAX di sepanjang jalur, β = nilai terbaik yang sudah dijamin untuk MIN. Jika α ≥ β, sisa anak node tidak perlu diperiksa (dipangkas).

Pseudocode
function AB(s, depth, alpha, beta, isMax):
  if terminal(s) or depth == 0: return eval(s)
  if isMax:
    v = -inf
    for c in succ(s):
      v = max(v, AB(c, depth-1, alpha, beta, false))
      alpha = max(alpha, v)
      if alpha >= beta: break      # pruning
    return v
  else:  # simetris dengan min dan beta
Kelebihan & Kekurangan

+ Hasil sama persis dengan Minimax tetapi lebih sedikit node dievaluasi; dengan urutan langkah terbaik, waktu turun dari O(b^m) menjadi O(b^(m/2)), artinya kedalaman pencarian dapat digandakan. − Pada urutan terburuk tidak ada pemangkasan (tetap O(b^m)); efisiensi sangat bergantung pada move ordering.

Kasus penggunaan yang cocok

Mesin catur dan permainan papan lain; hampir selalu dipakai bersama iterative deepening dan fungsi evaluasi.

⚠ Jebakan UTS: Alpha-beta tidak mengubah nilai di root, hanya mempercepat. Saat menelusuri, cabang yang dipangkas adalah yang menyebabkan α ≥ β. Jawaban "berapa node terpangkas" tergantung urutan anak, jadi ikuti urutan kiri ke kanan seperti soal.

6C. Panel Peta Konsep: Menghubungkan Semua Materi

Bagaimana konsep halaman 1 sampai 5 bekerja sama di dalam sistem Penerjemah Bahasa Isyarat?

1. Hierarki Piramida DIKW

  • Data: Matriks nilai piksel RGB mentah dari frame video.
  • Information: Koordinat ternormalisasi 21 titik sendi tangan (x, y, z).
  • Knowledge: Pola spasi-temporal yang dipelajari model ML untuk mengenali kata per gerakan.
  • Wisdom: Menerjemahkan kalimat sesuai konteks budaya/situasi percakapan secara tepat.

2. Automation vs Autonomy

  • Tahap Otomasi: Kamera memotong gambar & mengekstrak koordinat secara otomatis mengikuti skrip tetap.
  • Menuju Otonom: Sistem menjadi lebih otonom ketika mampu beradaptasi mandiri terhadap kecepatan isyarat pengguna baru, pencahayaan redup, dan mengoreksi salah prediksi dari konteks kalimat sebelumnya.

3. Knowledge Base & Inference

  • Knowledge Base: Bobot jaringan saraf (CNN/LSTM) yang telah dilatih berfungsi sebagai Learned Knowledge.
  • Inference: Proses forward pass saat memprediksi gestur baru.
  • Vs Sistem Pakar: Aturan IF-THEN buatan tangan gagal menangani variasi sudut tangan manusia, sedangkan ML mempelajari aturan fitur secara otomatis dari ribuan contoh data.

4. Peran Search Algorithm

  • Penyusunan Kalimat (Beam Search / Best-First): Saat merangkai urutan gestur [SAYA, MAKAN, NASI], algoritma mencari jalur kalimat terbaik dengan heuristik = skor probabilitas Language Model.
  • Pencarian Hyperparameter: Algoritma pencarian juga dipakai saat melatih model untuk mencari kombinasi learning rate & jumlah layer terbaik.
📌 Rangkuman Inti (Key Takeaways)
  1. AI mengubah Data menjadi Wisdom: Sensor mengumpulkan Data, prapemrosesan memberi Information, Machine Learning mengekstrak Knowledge, dan sistem pendukung keputusan menghasilkan Wisdom.
  2. Otonomi melampaui Otomasi: Otomasi mengeksekusi aturan tetap (IF-THEN statis), sedangkan sistem otonom mengevaluasi tujuan dan beradaptasi pada lingkungan yang belum pernah ditemui.
  3. Dua Paradigma Knowledge: AI klasik menggunakan hand-crafted rules di Knowledge Base + Inference Engine, sedangkan AI modern (ML) mempelajari knowledge langsung dari data berlabel.
  4. Uninformed vs Informed Search: Gunakan BFS/IDS untuk ruang tanpa bobot, UCS saat biaya langkah bervariasi, dan A* saat memiliki heuristik arah tujuan agar pencarian jauh lebih hemat dan tetap optimal.
  5. Sistem AI Nyata bersifat Hibrida: Aplikasi seperti Penerjemah Bahasa Isyarat menggabungkan visi komputer (fitur), Deep Learning (klasifikasi), dan Search Algorithm (Beam Search/A* untuk merangkai kalimat).

A. Uninformed Search (Tanpa Informasi Heuristik)

Kategori: Pathfinding

Breadth-First Search (BFS)

Menjelajah graf lapis demi lapis secara melebar. Menjamin jalur dengan jumlah langkah paling sedikit.

FIFO Queue Complete: Ya Optimal: Jika biaya seragam Time/Space: O(b^d)
  • Jalur terpendek graf tanpa bobot
  • Derajat koneksi jaringan sosial
  • Web crawler level dangkal

Depth-First Search (DFS)

Menelusuri satu cabang sedalam mungkin sebelum backtracking. Sangat hemat memori.

LIFO Stack Complete: Tidak (jika siklus) Optimal: Tidak Space: O(bm)
  • Penyelesaian maze / puzzle (Sudoku)
  • Deteksi siklus pada graf
  • Topological sorting

Uniform Cost Search (UCS)

Mengekspansi node dengan biaya kumulatif terendah g(n). Optimal untuk segala biaya positif.

Priority Queue g(n) Complete: Ya Optimal: Ya O(b^(1+⌊C*/ε⌋))
  • Rute jalan raya dengan tarif tol/kemacetan
  • Routing paket jaringan (OSPF/Dijkstra)

Depth-Limited Search (DLS)

DFS dengan batas kedalaman l untuk mencegah terjebak di cabang tak hingga.

LIFO Stack + Limit l Complete: Jika l ≥ d Optimal: Tidak Time: O(b^l) | Space: O(bl)
  • Pencarian pohon game dengan batas langkah
  • Eksplorasi direktori dengan batas subfolder

Iterative Deepening (IDS)

Menjalankan DLS berulang (l = 0, 1, 2...). Menggabungkan keoptimalan BFS dan hemat memorinya DFS.

Stack (Berulang) Complete: Ya Optimal: Biaya seragam Time: O(b^d) | Space: O(bd)
  • AI Catur / Game Tree yang sangat besar
  • Pencarian saat memori terbatas & d tidak diketahui

B. Informed Search (Memakai h(n), Fitness, atau Fungsi Evaluasi)

Kategori: Pathfinding

Best-First Search (umum)

Kerangka umum: selalu expand node dengan nilai f(n) terkecil. Greedy, UCS, dan A* adalah kasus khususnya.

Priority Queue f(n) Complete / Optimal: tergantung f(n) Time/Space: O(b^d) s.d. O(b^m)
  • Dasar perancangan algoritma pencarian baru
  • Weighted A*: cepat dengan toleransi biaya

Greedy Best-First Search

Selalu memilih node yang tampak paling dekat ke Goal menurut estimasi h(n) saja.

Priority Queue h(n) Complete: Tidak Optimal: Tidak Worst: O(b^m)
  • Perkiraan rute cepat saat waktu komputasi ketat
  • Pencarian dokumen relevan berbasis skor kemiripan

A* (A-Star) Search

Menggabungkan biaya riil g(n) dan estimasi h(n): f(n) = g(n) + h(n). Cepat dan optimal.

Priority Queue g(n)+h(n) Complete: Ya Optimal: Ya (h admissible) Time/Space: O(b^d)
  • Navigasi GPS (Google Maps / Waze)
  • Pathfinding karakter NPC di video game
  • Perencanaan gerak robot otonom

Kategori: Local Search

Hill Climbing (Local Search)

Hanya pindah ke tetangga langsung yang punya h(n) lebih baik; berhenti jika semua tetangga lebih buruk (local optima).

Single Current Node Complete: Tidak Optimal: Tidak Space: O(1)
  • Optimasi jadwal kuliah / shift kerja
  • masalah N-Queens & desain sirkuit

Hill Climbing Random Restart

Mengulang Hill Climbing dari state awal acak setiap kali terjebak, sehingga local optimum dapat dilewati.

Single Current Node + Loop Restart Complete: Probabilistik Optimal: Tidak dijamin Space: O(1)
  • 8-Queens / N-Queens skala besar
  • Penjadwalan & tuning parameter dengan banyak optimum lokal

Simulated Annealing

Seperti Hill Climbing, tetapi boleh menerima langkah yang lebih buruk dengan peluang eΔ/T; suhu T diturunkan bertahap.

Tetangga acak + jadwal suhu T Complete: Probabilistik Optimal: Tidak dijamin Space: O(1)
  • Penjadwalan & tata letak sirkuit
  • Traveling Salesman Problem

Local Beam Search

Menyimpan k state sekaligus; tiap iterasi memilih k successor terbaik dari gabungan semua beam.

k state (beam) Complete: Tidak Optimal: Tidak Space: O(k)
  • Decoding penerjemahan mesin & pengenalan suara
  • Penyusunan kalimat pada pipeline Bahasa Isyarat

Kategori: Optimisation

Genetic Algorithm

Populasi solusi berevolusi lewat seleksi, crossover, dan mutasi berdasarkan fungsi fitness.

Populasi + fitness Complete: Tidak dijamin Optimal: Tidak dijamin Space: O(N) populasi
  • Desain antena & bentuk sayap
  • Tuning hyperparameter & pemilihan fitur ML
  • Penjadwalan kompleks

Kategori: Adversarial (Permainan Dua Pemain)

Minimax

Untuk permainan dua pemain: MAX memaksimalkan nilai, MIN meminimalkan, dihitung dari daun ke root.

DFS pohon permainan Complete: Ya (pohon berhingga) Optimal: Ya (lawan optimal) Time: O(b^m) | Space: O(bm)
  • Tic-tac-toe, dam, Connect Four
  • Catur (dengan batas kedalaman + fungsi evaluasi)

Alpha-Beta Pruning

Minimax yang memangkas cabang tak relevan saat α ≥ β; hasil sama, evaluasi lebih sedikit.

Minimax + batas α, β Complete: Ya (pohon berhingga) Optimal: Ya (sama dengan Minimax) Time terbaik: O(b^(m/2))
  • Mesin catur & permainan papan
  • Dipasangkan dengan iterative deepening

8D. Rekomendator: Algoritma Mana yang Cocok?

Pilih karakteristik masalah, lalu lihat algoritma yang paling masuk akal beserta alasannya.

8E. Checklist Cepat Menjelang UTS
  • Hafal struktur data frontier: BFS = queue, DFS/DLS/IDS = stack, UCS = PQ(g), Greedy = PQ(h), A* = PQ(g+h).
  • Mampu menelusuri urutan expand dan menghitung g, h, f pada graf kecil, termasuk aturan tie-breaking (alfabetis bila diminta).
  • Mampu membuktikan atau membantah admissibility sebuah heuristik (bandingkan dengan h* sebenarnya).
  • Mampu menjelaskan kenapa BFS tidak optimal pada graf berbobot dan kenapa Greedy tidak optimal.
  • Mampu menyebut dan memberi contoh kelemahan Hill Climbing: local maximum, plateau, ridge, serta solusinya (random restart, stochastic, simulated annealing).
  • Mampu menggolongkan algoritma: Uninformed vs Informed, lalu kategori Pathfinding, Local Search, Optimisation, Adversarial.
  • Simulated Annealing: peluang menerima langkah buruk e^(Δ/T). Genetic Algorithm: populasi, fitness, seleksi, crossover, mutasi. Alpha-Beta: hasil sama dengan Minimax, α ≥ β → pangkas.
  • Pahami DIKW, automation vs autonomy, dan forward vs backward chaining (Bagian 1).
  • Mampu memilih algoritma berdasarkan karakteristik masalah (gunakan rekomendator 8D di halaman ini untuk latihan).
