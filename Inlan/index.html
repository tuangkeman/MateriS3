Langkah password recovery pada switch tanpa kehilangan konfigurasi lama.

Password Recovery
Jawaban singkat

Hubungkan kabel console → matikan switch → nyalakan sambil menahan tombol MODE hingga muncul prompt switch: → flash_init → rename flash:config.text flash:config.text.old → boot → jawab no pada setup dialog → enable → kembalikan nama file dan salin ke running-config → ganti password → copy running-config startup-config.

Penjelasan langkah demi langkah (interaktif)

Prinsipnya, file konfigurasi tidak dihapus. File tersebut hanya diganti namanya sementara agar switch boot tanpa membaca konfigurasi (dan password). Setelah masuk, file dikembalikan dan dimuat ke RAM, lalu password diganti. Contoh di bawah untuk Cisco Catalyst 2960.

1. Siapkan akses console

Sambungkan kabel console (rollover/USB) dari PC ke port console switch. Buka terminal emulator (PuTTY, Tera Term, minicom, atau screen) dengan setelan 9600 baud, 8 data bit, no parity, 1 stop bit, no flow control.

2. Masuk ke boot loader (ROMMON)

Cabut kabel daya switch. Tahan tombol MODE di panel depan, lalu pasang kembali kabel daya. Lepaskan tombol setelah sekitar 15 detik, ketika LED SYST berubah amber lalu hijau. Prompt switch: akan muncul.

3. Inisialisasi flash dan lihat isinya
switch: flash_init
switch: dir flash:   ! cari file config.text
4. Ganti nama file konfigurasi

Langkah ini membuat switch tidak menemukan konfigurasi saat boot, sehingga password tidak dimuat. File tidak dihapus.

switch: rename flash:config.text flash:config.text.old
switch: boot
5. Lewati setup dialog

Switch menyala dengan konfigurasi default dan menampilkan pertanyaan "Would you like to enter the initial configuration dialog? [yes/no]". Jawab no.

6. Masuk privileged mode dan kembalikan konfigurasi lama
Switch> enable
Switch# rename flash:config.text.old flash:config.text
Switch# copy flash:config.text system:running-config

Konfigurasi lama (VLAN, IP, hostname, dan lainnya) sekarang aktif kembali, dan Anda sudah berada di mode privileged.

7. Ganti password
S1# configure terminal
S1(config)# enable secret PasswordBaru
S1(config)# line console 0
S1(config-line)# password ConsoleBaru
S1(config-line)# login
S1(config-line)# line vty 0 15
S1(config-line)# password VtyBaru
S1(config-line)# login
S1(config-line)# end
8. Simpan dan cek interface
S1# copy running-config startup-config
S1# show running-config   ! pastikan konfigurasi lama utuh

Periksa apakah ada interface yang menjadi shutdown setelah konfigurasi disalin. Jika ada, aktifkan dengan no shutdown, lalu simpan lagi.

Tiga metode Frame Forwarding pada switch dan perbedaannya.

Switching
Jawaban singkat

Store-and-Forward: frame diterima utuh dan dicek FCS/CRC sebelum diteruskan, sehingga paling andal tetapi paling lambat. Cut-Through (Fast-Forward): frame langsung diteruskan setelah MAC tujuan (6 byte pertama) terbaca, sehingga tercepat tetapi tanpa cek error. Fragment-Free: frame diteruskan setelah 64 byte pertama terbaca, sebagai kompromi yang menyaring collision fragment (runt).

3

Tiga permasalahan jika memakai redundansi pada switch block tanpa Spanning Tree Protocol.

STP
Jawaban singkat

(1) Broadcast storm: broadcast berputar tanpa henti dan menghabiskan bandwidth serta CPU. (2) Ketidakstabilan tabel MAC: MAC address yang sama terus berpindah port. (3) Duplikasi frame unicast: host menerima salinan frame yang sama lebih dari sekali.

🌪️ Simulasi: satu broadcast pada loop tiga switch
Jumlah frame yang beredar: 0
Penjelasan lengkap
1. Broadcast Storm

Frame broadcast dibanjirkan ke semua port. Pada loop, frame itu terus kembali dan digandakan. Header Ethernet tidak memiliki TTL, sehingga frame tidak pernah mati. Bandwidth dan CPU switch habis, dan jaringan lumpuh.

2. Ketidakstabilan Tabel MAC

Switch melihat MAC sumber yang sama datang dari port berbeda secara bergantian, sehingga tabel MAC terus ditulis ulang (MAC flapping). Akibatnya, frame dikirim ke port yang salah atau dibanjirkan.

3. Multiple Frame Transmission

Frame unicast ke tujuan yang belum dikenal dibanjirkan dan tiba melalui beberapa jalur. Host tujuan menerima salinan ganda, yang dapat merusak protokol di lapisan atas.

STP (IEEE 802.1D) mencegah masalah ini dengan memblokir secara logis port yang menyebabkan loop. Port tersebut aktif kembali secara otomatis jika jalur utama putus.

4

Apa itu inter-VLAN routing? Sebutkan 3 metodenya.

Inter-VLAN
Jawaban singkat

Inter-VLAN routing adalah proses meneruskan lalu lintas dari satu VLAN ke VLAN lain menggunakan perangkat Layer 3 (router atau switch Layer 3). Ada tiga metode: (1) Legacy inter-VLAN routing, yaitu satu interface fisik router untuk setiap VLAN; (2) Router-on-a-Stick, yaitu satu interface router dengan subinterface 802.1Q melalui link trunk; (3) Switch Layer 3 dengan SVI, yaitu routing dilakukan di switch melalui interface VLAN virtual.

Penjelasan lengkap

Setiap VLAN merupakan broadcast domain dan subnet IP yang terpisah, sehingga host di VLAN berbeda tidak bisa saling berkomunikasi tanpa perangkat Layer 3.

Legacy

Setiap VLAN dihubungkan ke interface fisik router yang berbeda melalui port access. Metode ini sederhana, tetapi tidak skalabel karena jumlah interface router terbatas.

Router-on-a-Stick

Satu interface fisik router dibagi menjadi beberapa subinterface (misalnya g0/0.10, g0/0.20), masing-masing dengan encapsulation dot1Q. Biayanya murah, tetapi satu link bisa menjadi bottleneck.

Switch Layer 3 (SVI)

Dibuat interface vlan X beserta IP gateway, lalu diaktifkan dengan ip routing. Routing dilakukan di hardware, sehingga cepat dan skalabel. Metode ini paling umum di jaringan enterprise.

Lima langkah konfigurasi SSH pada switch agar bisa diakses secara remote.

SSH / Keamanan
Jawaban singkat

(1) Atur hostname; (2) atur ip domain-name; (3) crypto key generate rsa (≥ 1024 bit) dan ip ssh version 2; (4) buat username … secret … lokal; (5) pada line vty pasang transport input ssh dan login local.

! Prasyarat: switch punya IP manajemen & default gateway
S1(config)# interface vlan 1
S1(config-if)# ip address 192.168.1.2 255.255.255.0
S1(config-if)# no shutdown
S1(config-if)# exit
S1(config)# ip default-gateway 192.168.1.1

! Langkah 1 - hostname (tidak boleh default "Switch")
Switch(config)# hostname S1
! Langkah 2 - domain name
S1(config)# ip domain-name kampus.ac.id
! Langkah 3 - generate kunci RSA & aktifkan SSH v2
S1(config)# crypto key generate rsa general-keys modulus 1024
S1(config)# ip ssh version 2
! Langkah 4 - user lokal untuk autentikasi
S1(config)# username admin secret Rahasia123
! Langkah 5 - VTY hanya menerima SSH, login pakai user lokal
S1(config)# line vty 0 15
S1(config-line)# transport input ssh
S1(config-line)# login local
S1(config-line)# end
S1# show ip ssh                ! verifikasi

Uji dari PC: ssh -l admin 192.168.1.2

Tiga bagian Bridge ID suatu switch.

STP
Jawaban singkat

(1) Bridge Priority (4 bit, default 32768, kelipatan 4096); (2) Extended System ID (12 bit, berisi nomor VLAN); (3) MAC Address switch (48 bit). Total 8 byte.

🧮 Kalkulator Bridge ID
Penjelasan lengkap

Root bridge adalah switch dengan Bridge ID terkecil. Bagian yang dibandingkan pertama kali adalah priority (+ VLAN). Jika nilainya sama, MAC address terkecil yang menang. Priority diatur dengan spanning-tree vlan 10 priority 4096 atau spanning-tree vlan 10 root primary.

Apa tujuan penerapan per-VLAN spanning tree (PVST+)?

STP
Jawaban singkat

Menjalankan instance STP terpisah untuk setiap VLAN, sehingga root bridge dan port yang diblok bisa berbeda untuk setiap VLAN. Hasilnya adalah load balancing: semua link redundan terpakai, karena link yang diblok untuk satu VLAN tetap meneruskan trafik VLAN lain.

Penjelasan lengkap
  • Pada STP biasa (CST), satu topologi berlaku untuk semua VLAN, sehingga link yang diblok menganggur untuk seluruh VLAN.
  • Dengan PVST+, contohnya: DS1 menjadi root untuk VLAN 10 dan DS2 menjadi root untuk VLAN 20, sehingga kedua uplink aktif.
  • Rapid PVST+ (802.1w per VLAN) menambahkan konvergensi yang jauh lebih cepat.
DS1(config)# spanning-tree mode rapid-pvst
DS1(config)# spanning-tree vlan 10 root primary
DS1(config)# spanning-tree vlan 20 root secondary

Apa tujuan implementasi EtherChannel dalam topologi switch block?

EtherChannel
Jawaban singkat

Menggabungkan beberapa link fisik menjadi satu link logis untuk menambah bandwidth, menyediakan redundansi (jika satu link putus, trafik pindah ke link lain), dan membagi beban. Karena STP melihatnya sebagai satu link, tidak ada link yang diblok.

Penjelasan lengkap
  • Bandwidth: hingga 8 link aktif, misalnya 4 × 1 Gbps = 4 Gbps logis.
  • Tanpa blocking STP: link paralel tidak lagi diblok satu per satu.
  • Load balancing berdasarkan MAC/IP sumber atau tujuan.
  • Manajemen sederhana: konfigurasi cukup dilakukan pada interface Port-channel.
  • Protokol negosiasi: LACP (standar IEEE 802.3ad, mode active/passive) atau PAgP (Cisco, mode desirable/auto).
S1(config)# interface range fa0/1 - 2
S1(config-if-range)# channel-group 1 mode active
S1(config-if-range)# exit
S1(config)# interface port-channel 1
S1(config-if)# switchport mode trunk

Apa yang dimaksud FHRP dalam topologi ganda untuk mencegah single point of failure?

FHRP
Jawaban singkat

First Hop Redundancy Protocol (FHRP) adalah protokol yang membuat dua router atau lebih bekerja sebagai satu default gateway virtual (IP dan MAC virtual). Host cukup memakai IP virtual. Jika router aktif mati, router cadangan mengambil alih secara otomatis tanpa perlu mengubah konfigurasi host. Contohnya HSRP, VRRP, dan GLBP.

Penjelasan lengkap

Host biasanya hanya memiliki satu default gateway. Meskipun ada dua router fisik, jika gateway yang dipakai host mati, host kehilangan koneksi ke luar subnet. Inilah single point of failure di "hop pertama". FHRP menyelesaikan masalah ini:

HSRP

Milik Cisco. Satu router Active, satu Standby.

VRRP

Standar terbuka (RFC 5798). Satu Master, beberapa Backup.

GLBP

Milik Cisco. Menyediakan redundansi sekaligus load balancing ke beberapa router.

Jelaskan cara kerja HSRP.

HSRP
Jawaban singkat

Beberapa router membentuk satu grup HSRP yang berbagi IP dan MAC virtual. Router dengan priority tertinggi (default 100; jika sama, IP tertinggi yang menang) menjadi Active dan meneruskan trafik. Router berikutnya menjadi Standby. Kedua router bertukar pesan hello setiap 3 detik. Jika Standby tidak menerima hello selama 10 detik (hold time), Standby menjadi Active dan mengambil alih IP/MAC virtual.

Penjelasan lengkap
  • MAC virtual: HSRPv1 memakai 0000.0C07.ACxx (xx = nomor grup, 0–255). HSRPv2 memakai 0000.0C9F.Fxxx (grup 0–4095).
  • Hello dikirim ke multicast 224.0.0.2 (v1) atau 224.0.0.102 (v2) melalui UDP port 1985.
  • Preemption nonaktif secara default. Jika diaktifkan (standby preempt), router dengan priority lebih tinggi yang hidup kembali akan merebut peran Active.
  • Interface tracking menurunkan priority router jika uplink-nya mati, sehingga router lain mengambil alih.
  • State HSRP: Initial → Learn → Listen → Speak → Standby → Active.
  • Setelah failover, router baru mengirim gratuitous ARP agar tabel MAC switch diperbarui. Host tidak menyadari pergantian karena IP dan MAC gateway tetap sama.

HSRP · Lab
Jawaban singkat

R1(config-if)# no shutdown
R1(config-if)# end

R2(config-if)# end
