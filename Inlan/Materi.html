Port dan antarmuka

  • Half duplex: kirim atau terima bergantian (bisa tabrakan). Full duplex: kirim dan terima bersamaan (tanpa tabrakan).
  • Default: auto-negosiasi kecepatan dan duplex. Duplex tidak cocok di dua ujung = performa buruk dan banyak error.
  • Auto-MDIX: port otomatis menyesuaikan kabel straight atau crossover.

Modul 2: Konsep Switching

Frame Ethernet

PreambleSFDMAC TujuanMAC SumberTipeDataFCS
7 byte166246-15004
  • Ukuran frame valid: 64 sampai 1518 byte (tanpa preamble dan SFD). Di bawah 64 = runt, di atas 1518 = jumbo / baby giant.
  • FCS dipakai mendeteksi kerusakan data (frame rusak dibuang).
  • MAC address = 48 bit (12 digit heksadesimal). 3 byte pertama = OUI (kode pabrikan), 3 byte terakhir = nomor unik dari pabrikan.
JenisAlamat tujuan
UnicastSatu perangkat tertentu
BroadcastFF:FF:FF:FF:FF:FF, semua perangkat dalam jaringan
MulticastSekelompok perangkat. IPv4 mulai 01-00-5E, IPv6 mulai 33-33

Cara switch bekerja (animasi)

1. Frame masuk ke port. Switch belajar: catat MAC sumber + nomor port ke tabel MAC.
2. Switch cek MAC tujuan di tabel.
3a. Ada di tabel: teruskan (forward) hanya ke port itu.
3b. Tidak ada (atau broadcast): banjiri (flood) ke semua port kecuali port asal.
  • Tabel MAC (CAM) hapus entri otomatis setelah aging time 300 detik. Lihat: show mac address-table. Hapus: clear mac address-table dynamic.

Metode forwarding

MetodeCara kerja
Store-and-forwardTerima seluruh frame, cek FCS, baru kirim. Frame rusak dibuang. Dipakai Cisco (default), butuh buffer
Cut-throughMulai kirim setelah baca MAC tujuan, latensi sangat rendah, tanpa cek FCS. Ada 2 jenis: fast-forward (paling cepat) dan fragment-free (tunggu 64 byte pertama)

Domain tabrakan dan broadcast

  • Collision domain: tiap port switch = 1 domain tabrakan sendiri (hub: semua port satu domain).
  • Broadcast domain: semua port switch = 1 domain broadcast (tanpa VLAN). Router memisahkan broadcast domain.
  • Jaringan terlalu besar = banyak broadcast = performa turun. Solusinya: segmentasi dengan VLAN atau router.

Modul 3: VLAN

VLAN = pemisahan jaringan secara logis (satu VLAN = satu broadcast domain) tanpa peduli lokasi fisik. Manfaat: keamanan, hemat biaya, performa lebih baik, broadcast domain lebih kecil, IT lebih efisien, manajemen lebih mudah.

Jenis VLANKeterangan
Default VLANVLAN 1, semua port awalnya di sini, tidak bisa dihapus
Data VLANKhusus lalu lintas pengguna
Native VLANLalu lintas tanpa tag di trunk. Default VLAN 1, sebaiknya diganti (mis. 99)
Management VLANUntuk akses manajemen switch (SVI)
Voice VLANKhusus telepon IP (butuh prioritas dan delay rendah)
  • Rentang normal 1-1005 (disimpan di vlan.dat di flash). Rentang extended 1006-4094.

Trunk dan tag 802.1Q (animasi)

Trunk = link yang membawa banyak VLAN sekaligus. Frame diberi tag 802.1Q (4 byte): TPID 2 byte (0x8100), prioritas 3 bit, DEI 1 bit, VLAN ID 12 bit. FCS dihitung ulang. Frame native VLAN tidak diberi tag.

Konfigurasi

vlan 10
 name DATA                          ! buat VLAN + nama
interface f0/1
 switchport mode access             ! port untuk host
 switchport access vlan 10          ! masukkan port ke VLAN 10
interface g0/1
 switchport mode trunk              ! port untuk antar-switch
 switchport trunk native vlan 99
 switchport trunk allowed vlan 10,20,99
no vlan 10                          ! hapus VLAN
Hapus VLAN tapi port masih terpasang: port jadi tidak aktif sampai dipindah ke VLAN lain. Verifikasi: show vlan brief, show interfaces trunk, show interfaces f0/1 switchport.

Modul 4: Routing Antar-VLAN

Beda VLAN = beda subnet, jadi butuh perangkat Layer 3 agar bisa saling komunikasi. Tiga cara:

MetodeKeterangan
LegacySatu port fisik router per VLAN. Tidak skalabel, sudah ditinggalkan
Router-on-a-StickSatu link trunk ke router, dipecah jadi subinterface per VLAN
Switch Layer 3 (SVI)Routing di switch lewat interface VLAN. Paling cepat dan skalabel

Router-on-a-Stick (animasi)

interface g0/0/1.10                 ! subinterface untuk VLAN 10
 encapsulation dot1q 10             ! pakai tag VLAN 10
 ip address 192.168.10.1 255.255.255.0
interface g0/0/1.20
 encapsulation dot1q 20
 ip address 192.168.20.1 255.255.255.0
interface g0/0/1
 no shutdown                        ! aktifkan interface FISIK
! native VLAN: encapsulation dot1q 99 native
  • Port switch ke router harus mode trunk. Gateway host = IP subinterface VLAN-nya.
  • Kelemahan: satu link jadi bottleneck (semua lalu lintas antar-VLAN lewat satu kabel).

Switch Layer 3

ip routing                          ! aktifkan fungsi routing
interface vlan 10
 ip address 192.168.10.1 255.255.255.0
 no shutdown
interface g1/0/1                    ! port routed (tanpa VLAN)
 no switchport
 ip address 10.0.0.1 255.255.255.252

Troubleshooting: cek VLAN hilang, port trunk salah, native VLAN beda, allowed VLAN kurang, IP atau mask salah, gateway host salah.

Modul 5: Konsep STP

Link redundan mencegah putus, tapi di Layer 2 menimbulkan loop karena Ethernet tidak punya TTL. Akibatnya: broadcast storm, tabel MAC tidak stabil (MAC flapping), dan frame duplikat. STP (802.1D) memblokir sebagian port agar topologi bebas loop.

Topologi (animasi)

Titik biru = BPDU (pesan kontrol STP) dikirim tiap 2 detik, berisi Bridge ID = prioritas (default 32768, kelipatan 4096) + ID VLAN + MAC address.

4 langkah memilih topologi

1. Pilih Root Bridge: Bridge ID terendah menang (prioritas dulu, seri: MAC terendah).
2. Tiap switch non-root pilih Root Port: port dengan biaya jalur terendah ke root.
3. Tiap segmen pilih Designated Port (port yang meneruskan ke segmen itu).
4. Sisanya jadi Alternate / Backup = diblokir (tidak meneruskan data).
Kecepatan10 Mbps100 Mbps1 Gbps10 Gbps
Biaya (802.1D)1001942

Seri biaya: pilih Bridge ID pengirim terendah, lalu prioritas port terendah (default 128), lalu ID port terendah.

Status port dan timer 802.1D

Blocking (20 detik Max Age) → Listening (15 detik) → Learning (15 detik) → Forwarding; ada juga Disabled. Timer: Hello 2 dtk, Forward Delay 15 dtk, Max Age 20 dtk. Konvergensi lambat: 30-50 detik.

VarianKeterangan
STP (802.1D)Satu instans untuk semua VLAN, lambat

RSTP (802.1w)Konvergensi cepat. Status: Discarding, Learning, Forwarding
Rapid PVST+RSTP per VLAN (Cisco), pilihan yang dipakai di CCNA
  • PortFast: port host langsung Forwarding (jangan untuk link antar-switch). BPDU Guard: matikan port jika menerima BPDU.

spanning-tree vlan 1 root primary     ! jadikan root (prioritas 24576)

Menggabungkan beberapa link fisik menjadi satu link logis (Port-channel). Manfaat: bandwidth bertambah, redundansi, load balancing, dan STP menganggapnya satu link (tidak ada port yang diblokir).

Modul 7: DHCPv4

DHCPv4 memberi konfigurasi IP otomatis: alamat IP, subnet mask, gateway, DNS, lama sewa (lease). Server memakai UDP port 67, klien UDP port 68.

Proses DORA (animasi)

Discover: klien ➜ server. Broadcast, “Ada server DHCP?”
Offer: server ➜ klien. Unicast, menawarkan IP + pengaturan.
Request: klien ➜ server. Broadcast, “Saya ambil tawaran ini.”
Acknowledge: server ➜ klien. Unicast, konfirmasi dan mulai masa sewa.
Perpanjangan sewa: di 50% lease klien kirim Request unicast ke server asal. Jika gagal, di 87,5% kirim broadcast ke server mana pun.

Router sebagai server DHCP

ip dhcp excluded-address 192.168.10.1 192.168.10.9   ! alamat yang TIDAK dibagikan
ip dhcp pool LAN10                                   ! buat pool
 network 192.168.10.0 255.255.255.0
 default-router 192.168.10.1                         ! gateway
 dns-server 8.8.8.8
 domain-name contoh.local
 lease 2                                             ! sewa 2 hari
! matikan layanan: no service dhcp

Excluded-address dibuat sebelum pool agar alamat gateway/server tidak terbagi.

DHCP Relay

Broadcast tidak melewati router. Jika server di subnet lain, pasang relay di interface yang menghadap klien: broadcast diubah jadi unicast ke server.

interface g0/0/0
 ip helper-address 192.168.50.5     ! alamat server DHCP
interface g0/0/1
 ip address dhcp                    ! router sebagai KLIEN DHCP

Verifikasi: show ip dhcp binding (daftar IP terpakai), show ip dhcp pool, show ip dhcp server statistics, di PC: ipconfig /renew. Masalah umum: kabel/VLAN salah, pool habis, helper-address salah, alamat bentrok.

Modul 8: SLAAC dan DHCPv6

Alamat IPv6 penting

JenisKeterangan
Global Unicast (GUA)2000::/3, alamat publik
Link-LocalFE80::/10, hanya dalam satu link, otomatis ada di tiap interface
MulticastFF02::1 = semua node, FF02::2 = semua router
Unique LocalFC00::/7, mirip IP privat

Alur SLAAC (animasi)

Router Solicitation (RS, ICMPv6 tipe 133): host ➜ FF02::2, “Ada router?”
Router Advertisement (RA, tipe 134): router ➜ host, berisi prefix, panjang prefix, gateway.
Host buat alamat sendiri: prefix dari RA + Interface ID (EUI-64 atau acak).
DAD (Duplicate Address Detection): host kirim Neighbor Solicitation untuk memastikan alamat tidak bentrok. Aman = alamat dipakai.

EUI-64: ambil MAC 48 bit, sisipkan FFFE di tengah, lalu balik bit ke-7. Contoh: MAC 00:1A:2B:3C:4D:5E menjadi 021A:2BFF:FE3C:4D5E.

Tiga metode (diatur oleh flag di RA)

MetodeFlagSiapa kasih apa
SLAAC sajaA=1, O=0, M=0Alamat dari RA. Info lain (DNS) tidak ada
SLAAC + DHCPv6 statelessA=1, O=1, M=0Alamat dari SLAAC, DNS dkk dari server DHCPv6
DHCPv6 statefulM=1, A=0Server DHCPv6 beri alamat lengkap + info dan mencatat klien

Pesan DHCPv6: SOLICIT, ADVERTISE, REQUEST, REPLY. Port: klien UDP 546, server UDP 547. Klien mengirim ke multicast FF02::1:2 (semua server dan relay DHCPv6).

Konfigurasi router

ipv6 unicast-routing                  ! WAJIB agar router kirim RA
interface g0/0/1
 ipv6 address 2001:db8:acad:1::1/64   ! SLAAC saja: cukup ini

! --- Stateless DHCPv6 ---
ipv6 dhcp pool STATELESS
 dns-server 2001:db8:acad::254
 domain-name contoh.local
interface g0/0/1
 ipv6 nd other-config-flag            ! set O=1
 ipv6 dhcp server STATELESS

! --- Stateful DHCPv6 ---
ipv6 dhcp pool STATEFUL
 address prefix 2001:db8:acad:1::/64 lifetime infinite infinite
 dns-server 2001:db8:acad::254
interface g0/0/1
 ipv6 nd managed-config-flag          ! set M=1
 ipv6 nd prefix default no-autoconfig ! set A=0
 ipv6 dhcp server STATEFUL

! --- Relay (server beda subnet) ---
interface g0/0/0
 ipv6 dhcp relay destination 2001:db8:acad:2::5 g0/0/1
! --- Router sebagai klien ---
interface g0/0/1
 ipv6 enable
 ipv6 address autoconfig              ! SLAAC  (atau: ipv6 address dhcp)

Verifikasi: show ipv6 interface, show ipv6 dhcp pool, show ipv6 dhcp binding, show ipv6 dhcp interface.

Modul 9: Konsep FHRP (Redundansi Gateway)

Host hanya punya satu default gateway. Jika router itu mati, host terputus dari luar jaringan walau ada router cadangan (single point of failure). FHRP (First Hop Redundancy Protocol) menyelesaikannya: beberapa router fisik berbagi satu router virtual dengan IP virtual dan MAC virtual. Host memakai IP virtual itu sebagai gateway, jadi saat router utama mati, host tidak perlu mengubah apa pun.

Failover (animasi)

1. Host kirim lalu lintas ke IP virtual. Router Aktif yang meneruskan.
2. Router Aktif mengirim pesan hello berkala. Router Standby memantau.
3. Router Aktif mati: hello berhenti. Standby menunggu sampai hold time habis.
4. Standby mengambil alih IP dan MAC virtual, jadi Aktif. Host lanjut tanpa ubah pengaturan.

Satu lagi: IRDP (ICMP Router Discovery Protocol), hanya IPv4, host menemukan router lewat pesan ICMP. Versi IPv6: HSRP untuk IPv6, VRRPv3, GLBP untuk IPv6.

HSRP lebih dalam

  • Router dengan prioritas tertinggi jadi Aktif. Seri prioritas: IP address tertinggi menang.
  • Preempt: router berprioritas lebih tinggi merebut kembali peran Aktif. Di HSRP preempt tidak aktif secara default (VRRP: aktif).
  • MAC virtual: HSRPv1 0000.0C07.ACxx, HSRPv2 0000.0C9F.Fxxx (xx = nomor grup). Grup: v1 0-255, v2 0-4095. HSRP memakai UDP 1985.
  • Status HSRP berurutan: Initial, Learn, Listen, Speak, Standby, Active.
  • Load balancing HSRP: buat dua grup (mis. VLAN 10 Aktif di R1, VLAN 20 Aktif di R2), supaya kedua router terpakai.
! R1 (dibuat Aktif)
interface g0/0/1
 standby version 2
 standby 1 ip 192.168.1.254         ! IP virtual = gateway host
 standby 1 priority 150             ! lebih tinggi dari default 100
 standby 1 preempt                  ! rebut peran Aktif kembali
! R2: cukup "standby 1 ip 192.168.1.254" (prioritas default 100)
! verifikasi: show standby   atau   show standby brief
Gateway di PC harus diisi IP virtual (192.168.1.254), bukan IP asli R1 atau R2.

GLBP singkat

AVG (Active Virtual Gateway) membalas ARP host dengan MAC virtual berbeda-beda (default bergiliran), sedangkan tiap AVF (Active Virtual Forwarder) meneruskan lalu lintas. Hasilnya beban terbagi otomatis ke beberapa router.
